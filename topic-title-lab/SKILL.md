# 最强师傅·选题标题边界新版

> 本模块必须遵守 [不可跳步执行协议](../WORKFLOW_PROTOCOL.md)：按本模块写明的 Step、选择门、检查项和判停点顺序完成；已有输入记为该步已完成，只有用户明确要求才跳过。

> 实验目标：修复“把对外标题写成内容摘要”的真实失败。标题负责让对的人停下来，内容负责兑现价值。

## 0. 实验边界

- 本模块只负责已有方向之后的对外标题，不接管从零找方向的 `topic-engine`。
- 只处理选题确定之后的标题包装边界，不重做账号定位、选题发现、研究、脚本、拍摄或发布。
- 不把一个真实失败扩张成唯一公式；不同内容可以用好奇、代入、反差、利益或搜索需求驱动。
- 不虚构人物、经历、数字、结果或冲突；标题承诺必须能由内容兑现。
- 安装、合并、发布或上传需要用户另行授权。

## 1. 先判断是不是本实验负责

### 应触发

内容方向、内部选题或核心问题已经存在，并且用户出现任一信号：

- “只给标题 / 先别写内容”；
- “只看选题”，且上下文已有内容方向、核心问题或 `topic-engine` 的内部短名单；
- “别把答案、方法或完整故事写进标题”；
- “让目标观众停下来 / 更有代入感 / 更想点进去”；
- “把这些内容方向包装成标题”；
- 已从 `topic-engine` 得到内部短名单，现在要生成对外可见标题。

### 不应触发

- 完全没有具体内容方向，只想从零找账号选题：回原 `topic-engine`；
- 说“只看选题”但没有方向、问题或可用素材：仍回原 `topic-engine`，不能把标题包装冒充选题发现；
- 选题已经确定，要写研究底稿或完整口播：去相邻内容生产流程；
- 只要把现有内容总结成一句话：这是内容提炼，不是标题包装；
- 用户明确要标题概括全部信息：按用户要求总结，不强行制造悬念；
- 标题与正文主题无关，只想骗点击：拒绝标题党。

### 歧义处理

“帮我想选题”可能有两层意思：

- 不知道讲什么 → 选题发现，由原 `topic-engine` 负责；
- 已知道讲什么，只是不知道对外怎么写 → 本实验负责。

只有用户原话或材料已经明确“方向已定、只要对外标题”时，才把这一步记为“已由用户输入完成”并执行；不能凭模型偏好替用户选择题型、承诺或方向。确实无法判断时，只问一句：“你现在缺的是内容方向，还是对外标题？”

## 2. 分开三个层级

1. **选题内核**：创作者内部真正要讲的问题、机制或价值。
2. **对外标题**：目标观众为什么愿意停下、点开。
3. **内容承诺**：点开之后，正文必须回答或兑现什么。

三者不是同一句话：

- 标题要和选题内核共享同一目标人群、核心矛盾或问题；
- 标题不必带上支撑事实、完整案例、原因、步骤和结论；
- 内容必须兑现标题承诺，不能借一个无关情绪骗点击。

可以记成：**强关联观众为什么点，弱关联正文具体怎么讲。**

## 3. 根据任务选择标题模式

只选最合适的模式，不得每题套同一公式。

### A. 钩子标题（默认）

适合知识口播、观点、关系、职场、运营等内容。选择一个主要驱动：

- 好奇：保留一个观众不知道的原因或结果；
- 代入：让目标观众觉得“这说的不就是我”；
- 反差：两个通常不该同时出现的状态发生冲突；
- 利益：让观众知道点开后能减少什么损失或获得什么判断。

默认隐藏解释、方法和结论，不要求具体人物、时间和完整故事。

### B. 故事标题（仅在素材或用户要求支持时）

用户明确要案例型、人物型或故事型标题时，才可以使用具体现场、人物、事实冲突或结果悬念。

- 只保留推动点击所必需的细节；
- 不把人物、背景、过程、结果全部塞进一行；
- 用户没有提供的事实不得补写。

“具体现场 + 多个事实相撞 + 结果”不是默认规则。

### C. 搜索/实用标题

用户明确要搜索流量、教程或问题解答时，可以直接放目标关键词与问题，但仍不必提前写完全部答案。

## 4. 标题生成流程

### 第一步：冻结内容承诺

先在内部写清：正文到底能回答哪个问题、解释哪个矛盾或交付哪个判断？没有可兑现承诺时，不进入标题生成。

同时建立一份**标题事实白名单**：只记录用户材料中逐字可追溯的对象、动作、数量、时间和结果，以及已明确标注的确定程度。标题中的具体名词、数量、场景和比喻都必须能回到这份白名单；不能把“每天列 12—15 项”扩写成“写满一页”，也不能把“完成天数变多”升级成“效率提高”。

### 第二步：确定目标观众的停留理由

只选一个主要理由：好奇、代入、反差、利益或搜索。不要一条标题同时承担所有使命。

### 第三步：生成候选

- 数量按用户要求；未指定时给 5 个。
- 默认至少覆盖 3 种不同驱动，避免所有标题都是同一句式。
- 标题应简洁有力，但不设置机械字数上限。

### 第四步：做“摘要删除”

逐条检查并删除非必要信息：

- 支撑结论的全部事实；
- 完整故事背景；
- 原因解释；
- 方法步骤；
- 最终答案或结论。

删除后仍要让目标观众知道“这和我有关”，不能删成空洞谜语。

再做两道硬检查：

1. **逐词事实回查**：标题中的人物、场景、数量、程度词和比喻，是否都能由标题事实白名单支持？只是听起来合理但材料没说的，一律删除或改回原事实。
2. **假设泄漏检查**：如果正文把某个机制标成“可能解释、推断、待验证”，标题不得把它写成答案或既定事实。标题可以呈现已观察到的现象和问题，把“任务切换、优先级稀释、清单没有重点”等候选解释留给正文回答。

### 第五步：做“承诺兑现”检查

每条标题内部回答四问：

1. 目标观众会停一下吗？
2. 她会觉得和自己有关吗？
3. 她是否还不知道答案，因而有点开的理由？
4. 正文能否真实回答这条标题提出的问题？

任一答案为否，重写或淘汰。

## 5. 输出规则

- 用户说“只看标题 / 只给选题”：只输出编号标题，不附内容摘要、拍法和解释。
- 用户要比较理由：标题后只标注主要驱动，不展开正文。
- 用户同时要标题和内容方向：严格分成两栏，不能把两栏合并成长标题。
- 用户只要一个：给一个最终标题，不附赠五个备选。
- 不提前写出原因、三步方法或完整结论，除非用户明确要求总结式标题。
- 用户同时要求“标题 + 正文待回答问题”时，候选机制可以放在问题里作为待检验项，但不能提前写进标题当答案。
- “只看选题”不等于“只输出标题”：若用户没有明确要对外标题，先保留内部选题与标题包装的边界，不擅自把内部规划改写成标题。

## 6. 禁止项

- 把“内容讲了什么”当成标题必须复述的内容；
- 强制每个标题都使用人物 + 时间 + 两个事实 + 结果；
- 一串标题全部使用同一种“为什么……反而……”句式；
- 为了反差编造用户没有提供的经历、结果或数字；
- 把材料里的数量、场景或程度改写成未经提供的新事实、新比喻或更强结论；
- 把“可能机制 / 本轮推断 / 待验证解释”提前写成标题中的确定答案；
- 用与正文无关的情绪、身份或冲突骗点击；
- 用焦虑、恐惧、羞辱或绝对化承诺替代真实吸引力；
- 把“只看选题”理解成顺带输出完整内容方案。

## 7. 完成标准

只有同时满足以下条件，标题候选才算完成：

- 选题内核、对外标题和内容承诺没有混写；
- 标题没有提前说完故事、原因、方法和结论；
- 目标观众、核心矛盾或问题与正文一致；
- 至少保留一个真实的信息缺口或代入理由；
- 正文能够兑现标题承诺；
- 没有编造、标题党、焦虑营销或单一公式滥用；
- 标题每个具体事实均能回到事实白名单，且没有假设泄漏；
- 输出严格服从用户要“只看标题”还是“标题 + 内容方向”。

## 8. 与新版相邻路由的关系

- 用户从零找方向或说“只看选题”但没有方向：由 `topic-engine` 负责；本模块只接收已有方向、核心问题或内部短名单。
- 用户明确只要对外标题：本模块作为唯一 owner；不要同时启动 `opening-selector` 或 `expectation-contrast`。
- 用户要标题且已经明确要求真实反差：本模块仍负责标题交付，最多把 `expectation-contrast` 作为一个增强器检查真实两端；不能让两个模块同时当 owner。
- 用户只要选择开头结构：转 `opening-selector`；用户要完整脚本：转 `viral-factory`，本模块不接管整稿。

静态通过、模拟验收、真实用户认可和发布效果必须分开报告。
