# 新版 Skill 契约

```yaml
identity:
  technical_id: zuiqiang-shifu-depth-lab
  display_name: 最强师傅·内容深挖新版
job:
  user: 需要制作知识型真人口播的创作者
  repeated_task: 把已有选题从常识回答升级为有机制、有证据、有稀缺增量且像真人说话的口播
  success: 观众获得一个普通同类内容不容易提供的非显然判断，能理解其因果机制，并知道如何核验或行动
scope:
  owns:
    - 写作前的研究与问题收窄
    - 机制链、证据账本、竞争解释与边界
    - 与机制对应的行动价值
    - 成稿稀缺价值、真人表达和通用废话过滤
    - 深度成稿按用户确认的表达风格生成；选择融合时才经过爆款表达层，选择不融合时保持清楚自然但不主动追求爆款结构
    - 实验用口播成稿和证据说明
  excludes:
    - 普通标题、封面、轻量改稿和朋友圈
    - 账号定位、选题发现、拍摄、剪辑、发布和投流
    - 模仿作者风格或整包蒸馏播客
    - 安装、覆盖或发布全局最强师傅
routing:
  should_trigger:
    - 写得更深入、更有干货和知识密度
    - 解释背后逻辑、商业模式、利益关系或制度机制
    - 现有口播太浅，只有常识或观点
    - 需要事实、案例、研究与来源支撑
    - 题目已确定但受众时长资料未齐，当前先拆机制证据或研究问题
  should_not_trigger:
    - 只改标题、开头、语气、错别字和篇幅
    - 朋友圈、通知、剧情、段子或纯情绪内容
    - 用户已给完整论证，只需口语化
    - 还没有选题或正在做账号定位
  near_neighbors:
    - zuiqiang-shifu/viral-factory: 不负责生成研究深度；仅在用户选择融合爆款风格时作为内置表达层，负责具体进入、低理解成本、口播节奏、共鸣和传播性，不算第二个 owner，也不得改写事实锁
    - zuiqiang-shifu/topic-engine: 负责找选题，不负责研究既定选题
inputs:
  required:
    - 已确定的知识型选题
  optional:
    - 目标受众
    - 期望时长或内容形态
    - 用户已选择的对外内容角度、时长和是否融合爆款风格，或是否明确委托系统决定；只要研究底稿/证据账本/诊断时，表达风格记为已检查不适用
    - 用户材料和限定来源
    - 是否允许联网研究
    - 账号语气和禁区
outputs:
  artifacts:
    - 角度、时长、是否融合爆款风格的候选、推荐理由与取舍（仅在用户尚未选择时先外显，并停在选择门）
    - 最终口播稿（用户要成稿时默认唯一外显）
    - 深度底稿摘要（默认内部，用户明确要求时外显）
    - 证据说明与来源（默认内部，用户要求来源或风险需要时外显）
    - 自检结果（默认内部，用户明确要求审计时外显）
  quality_invariants:
    - 对外内容角度、时长和是否融合爆款风格由用户最终确认；系统负责推荐和解释，不把推荐冒充最终决定；本轮不生成口播时必须记录表达风格已检查不适用，不能无痕省略
    - 用户已明确选择或说“按你推荐的来 / 你替我选”时直接推进，不重复确认；同一选择门中的三项推荐可被“按你推荐的来”一并确认
    - “直接写 / 直接继续 / 赶时间”不自动等于委托代选；只有用户明确跳过某项时才记录为跳过
    - 一个中心机制
    - 底稿可比较候选机制，但成稿只保留一个主镜头，最多一个辅助镜头
    - 至少三环因果
    - 每条因果箭头标注事实、来源观点、推断或未知
    - 个案、相关和未经控制的前后记录不直接当作因果证明
    - 不补造样本、对照、百分比或效果大小
    - 事实观点推断未知分开
    - 内部至少考虑两个可信的竞争解释并记录筛选依据，另保留一个边界；成稿只写会改变核心判断或行动的最强竞争解释或边界
    - 行动与机制对应
    - 深度不能停在通用流程，至少落到一个本题相关的成本、收益、取舍、判断权、能力积累或后果
    - 每题都检查二阶影响；证据允许时解释至少一个会改变判断的二阶影响，如激励延续、规模反馈、价值转移、时间错位或收益风险分离；证据不允许时记录已检查不适用及具体证据缺口
    - 成稿至少提供一种稀缺增量：隐藏机制、非显然区分、决策门槛、失败条件或可迁移框架
    - 通用常识、免责话、内部边界和不改变判断的正确提醒默认不外显
    - 核心判断有本题中的具体人、动作、取舍或后果支撑，不靠工整抽象总结制造真人感
    - 用户选择融合爆款风格时才完成爆款表达层；爆款感来自具体冲突或立即有用的判断、低理解成本、节奏推进和观众关联，不靠末尾互动问题补足
    - 用户选择不融合爆款风格时不暗中加入钩子、强反差和传播模板，同时保持能直接朗读的清楚真人表达
    - 结尾保持与前文相同的说话者、矛盾和因果线；不在末段第一次追加清单、判断框架、互动 CTA 或抽象金句
    - 真实未决问题和机制支持的具体行动可以结尾；不能因禁用强行互动而误删所有问句或祈使句
    - 低证据时交付最小事实、假设、补证、小实验与停止条件
    - 对外交付严格服从用户要求的时长数量格式，不用内部底稿增加表演性复杂度
workflow:
  decisions:
    - 是否触发
    - 用户选择的对外角度、时长和是否融合爆款风格；若要口播且未选择，先给推荐、理由和取舍并等待确认；若不生成口播，记录表达风格已检查不适用
    - A决策/B解释/C研究诊断
    - 来源限定/联网研究/假设草稿
    - 选择一个主机制镜头
  steps:
    - 通过用户角度、时长和表达风格选择门；用户已有答案时记为该项已完成，明确委托时采用推荐，只有明确要求时才跳过；研究底稿/证据账本/诊断不生成口播时把表达风格逐项记为已检查不适用
    - 冻结问题与观众价值
    - 形成至少两个可信竞争解释并记录筛选依据
    - 研究并建立证据账本
    - 构建机制链和边界
    - 形成行动价值
    - 写口播并自检；选择融合时完成 viral-factory 内置爆款表达层并复核事实锁，选择不融合时执行非爆款真人表达检查
    - 执行末句与末段删除测试，选择因果后果、人物选择/结果、具体行动/停止条件或真实未决问题作为自然落点
    - 逐句执行观众价值、通用插入和真人朗读检查
    - 只显示用户明确要求的成品或证据层，隐藏其余内部工作记录
    - B型具体事件可压缩为事件段→机制段→应对段；其他类型不强行套用
failure_handling:
  missing_input: 缺少角度、时长或表达风格时先给少量选项、推荐和取舍并等待；其余输入用最小假设继续并明确缺口，不能因此编造事实
  conflict: 并列冲突来源和解释，降低结论强度
  out_of_scope: 退回原最强师傅的相邻路由
trust:
  reads:
    - 用户提供的材料
    - 经授权的公开网页与本地参考资料
  writes:
    - 仅用户批准的实验工作区和证据目录
  external_actions: []
  approval_points:
    - 安装、合并、发布、上传和账号操作另行批准
validation:
  static:
    - package validation
  routing:
    - 正例、反例和近邻混淆题
  execution:
    - 奶茶加盟、五星酒店、优绩主义三类题材
    - 深度机制完整且具有爆款口播表达的回归题
    - 用户未选表达风格时必须停门、选择融合后确实融合、选择不融合后不暗中加入爆款结构、研究模式明确记录表达风格不适用的四类回归题
    - 竞争解释至少两项，以及二阶影响支持/不支持均留下检查记录的回归题
    - 因果已闭合后追加相关三问的自然收尾回归题
    - 合法行动结尾与真实未决问题的反过度修正题
  real_user_signal:
    - 用户对新旧稿深度、可信度和可用性的明确选择
```
