# 行动闭环

## 一、先判断该给哪种行动

“有价值”不等于每篇都要给五个步骤，也不等于结尾要给方法。结尾规则见根 [SKILL.md](../../SKILL.md) 的“深度成稿的表达选择与自然收尾”和 [VOICE_RULES](../../VOICE_RULES.md) 第一节第 8 条：结尾不负责给方法，方法放正文讲透。

### A 决策行动型

适合“要不要加盟、怎么买、怎么判断、怎么执行”。底稿必须完成六格，成稿把它们放进正文主体讲透（怎么做、一个具体例子、哪里最容易做错），不集中到结尾：

1. 触发场景：什么时候用；
2. 所需输入：需要哪些真实材料；
3. 步骤：按什么顺序做；
4. 交付物：最后得到什么；
5. 验收标准：怎样算做对；
6. 失败与回退：什么情况下停止、换方案或补资料。

### B 机制解释型

适合“为什么出现这个现象”。不要假装能替行业经营者给完整方案。底稿保留最能区分解释、改变判断的 1—3 项，不为凑数量硬塞三个：

- 三个核验问题；或
- 三个可观察信号；或
- 一个用于判断相似现象的框架。

这些项目留在底稿，是行动价值的后台设计。**机制解释型的成稿默认不带行动段**：讲清楚为什么，停在最后一个因果后果、反转、回到开头的冲突，或本题还没解决的矛盾。核验问题和观察信号留在底稿给用户自己用；只有用户明确要“那该怎么办”，或某个信号必须在正文里出现、观众才看得懂机制时，才把它写进对应的机制段，仍然不放到结尾。

### C 研究诊断型

适合教育、组织和社会问题。可提供：

- 一个低风险个人实验；
- 一个组织可以调整的评价或激励杠杆；
- 一组用于继续观察的问题。

这些放在正文讲到对应机制的地方，不当结尾。如果材料只能解释问题，就交付一个由机制支持的判断；观察方向和核验动作留在底稿。连这个都无法支撑时停止扩写；只有用户明确要研究诊断或缺口说明时，才解释缺少什么，不在口播里添加“本文不提供完整解法”之类的元说明。

## 二、行动必须接在机制上

```text
机制：用户被总部样板店误导
行动：只比较同城、同面积、同商圈门店

机制：关键风险出现在持续采购与退出
行动：核对供应价、起订量、违约、押金和设备处置条款
```

不合格行动：

- 保持理性；
- 提升认知；
- 多去尝试；
- 相信自己；
- 具体问题具体分析。

除非后面继续给出可观察、可完成的动作。

六格、问题清单和停止条件是内部闭环，不等于要逐项念给观众，更不等于要集中放在结尾。成稿优先用一个具体场景承载方法：谁拿什么材料做了哪一步，看到什么结果时继续，看到什么结果时停。若行动可以原样放进大量同类文章，说明它还没有接到本题机制上。

## 三、短口播的行动压缩

以下只适用于 A 决策行动型和用户明确要行动的 C 型。90秒内最多保留：

- 一个决策框架；或
- 1—3 个真正改变判断的核验问题；或
- 一个小实验和一个停止条件。

不要在结尾突然塞入“五步法”或“三个问题”。即使清单与主题相关，只要它在末段才第一次出现、只是把正文重新分类，或让说话者从分析者突然变成老师，也应删除或前移。结尾也不写“下次你……”“先问一句……”“记得……”，不替观众保证效果。真实未决问题可以作为落点，但它是本题还没解决的矛盾，不改写成“你是不是也这样”的互动 CTA，也不改写成给观众的作业。

## 四、验收问题（只用于 A 决策行动型，以及用户明确要行动的 C 型）

- 观众明天能拿什么材料开始？
- 做完后能得到什么可检查结果？
- 什么情况说明这个方法不适用？
- 动作是否直接回应主机制？
- 是否把专家、组织或政策问题错误转嫁给个人？

B 机制解释型不按上面五问验收，改问两件事：机制讲到观众能复述了吗？结尾有没有偷偷补一段行动？
