# 预期违背与可记忆反差

> 本模块必须遵守 [不可跳步执行协议](../WORKFLOW_PROTOCOL.md)：按本模块写明的 Step、选择门、检查项和判停点顺序完成；已有输入记为该步已完成，只有用户明确要求才跳过。

这个 Skill 保留原语境里的强弱对比、冒犯感、冲突感及其力度。它们不是需要被删掉的“过激措辞”，也不是可以脱离事实自由加码的刺激词；本 Skill 把强词还原为一条可执行、可否决的反差动作链。

## R — 原文（Reading）

> “一个视频如果你不会写开篇，有一个最有流量最安全的方法，就是用强弱对比。”
>
> —《短视频爆款开篇公式：用「强弱对比」秒抓流量》，原文第37行（S04）

> “冒犯感是一种吸引力，是一种不讲道理的反差，是一种违背本能的展现效果。”
>
> —《好文案的核心密码：用「冒犯感」制造记忆点》，原文第40行（S10）

> “所谓这个打造，其实就是发现这个人本身身上的冲突……体现的方式就变成了对抗、反转、悬念、意外。”
>
> —《IP打造核心逻辑：用冲突感快速立住人设》，原文第39行（S14）

以上三段均是来源内口述；本 Skill 采纳的是“打破默认预期、找到真实不一致、把张力转成可观看表达”的动作，不把其中的流量效果或固定强度当作已证实定律。

## I — 方法论骨架（Interpretation）

这个 Skill 处理的是“表达太顺，观众能猜到下一句”的问题，不是要求每条内容都炸。

1. 先写目标观众对这个主题的默认预期：他通常会怎样理解、怎样判断、下一句会猜什么。
2. 只从真实材料中找一个与预期不一致的事实、结果、身份、场景、顺序或词语关系。
3. 选择一个可比的反差维度，让两端在同一问题上可比较，而不是随意拿两个极端拼接。
4. 用强弱对比呈现结果差，用冒犯感打破惯常词组，或用冲突感呈现身份/目标的不一致；术语可以有力度，事实不能被加码。
5. 把两端并置成一句标题、开头、画面关系或故事入口，并保留必要条件和未知项。
6. 最后把反差明确回扣到主题：它必须帮助观众理解一个问题、判断或选择，而不只是让人停一下。
7. 如果不存在真实差异、差异不可比、事实支点不足，或反差无法解释主题，就否决该表达，停止编造。

## A1 — 来源内教学/转述示例（作者亲自应用证据不足）

以下材料能说明讲者如何使用这套思路教学和改写，但语料没有提供足够证据证明这些案例均由讲者本人实际执行。这里保留方法示范，不把它们包装成作者亲自做成的成功案例。

### 案例 1：“二十六个字母都不会，在美国生活七年”

- **问题**：平铺“在美国生活七年”只是经历介绍，观众没有立即可追问的差异。
- **方法论的使用**：把“长期生活”与“基础能力极弱”放在同一经历语境里，形成身份/能力的强弱反差，再把它作为开篇。
- **结论**：当两端都指向同一经历时，反差能把普通主题改成一个观众想知道原因的问题。
- **结果**：来源内说法是“这个视频就有人看”；视频、账号、数据和因果未核验，只能作为教学案例。
- **证据状态**：来源内教学示例；事实与传播效果未核验（S04，原文第37行）。

### 案例 2：“香的令人发指”描述咖啡

- **问题**：精益求精、甄选、经典等常规赞美可以互换，产品卖点没有记忆钩子。
- **方法论的使用**：把“香”与通常用于严重负面评价的“令人发指”并置，用冒犯感打破礼貌赞美的语言预期，同时仍指向咖啡口感。
- **结论**：不寻常的词语搭配能制造可记忆的意外，但它必须能被理解并回到产品事实。
- **结果**：作者口头判断该写法“胜出”；没有受试者、投放或销售对照，效果未核验。
- **证据状态**：来源内教学演示；传播与商业效果未核验（S10，原文第40行）。

### 案例 3：“臭卖面条的”与“十八个亿流量”

- **问题**：普通身份与成功结果若分别陈述，人物容易只剩自夸，缺少能追问的张力。
- **方法论的使用**：把“卖面条的”这一普通身份与极大的流量结果放在同一句里，制造身份—结果冲突，再引导观众追问“凭什么”。
- **结论**：人物反差可以来自身份与结果的不一致，不必凭空添加传奇优点。
- **结果**：原文把十八个亿作为口头事实；无原账号、时间、平台或数据来源，人物与数字均未核验。
- **证据状态**：作者转述案例；事实、效果和因果未核验（S14，原文第39行）。

## A2 — 触发场景（Future Trigger）★

### 用户会在什么情境下需要这个 Skill？

1. 主题、标题或开头太平，用户想把“某行业/某产品/某经历”改成强弱对比，但手里已有真实项目、结果或身份材料。
2. 用户说想要“冒犯感”“不讲常规”“更有记忆点”，实际需要的是一个不寻常但仍说得通的词语组合，而不是攻击某个人。
3. 用户有真实的身份—结果、前后状态、场景—行为或顺序反差，想把它变成开头、标题、口播或 IP 入口。
4. 用户想做“反常识”表达，又担心夸张、误导或和主题脱节，需要同时生成候选并判断能否使用。
5. 用户明确要求“没有数据也造一组极端反差”；此时仍由本 Skill 接住做真实性、可比性和主题门审查，但只能否决、补问或给明确标注的假设练习。

### 语言信号（用户的话里出现这些就应激活）

- “帮我做强弱对比/加一点反差/这个开头太平了。”
- “要有冒犯感、冲突感、反常识，但别变成骂人。”
- “Make it more contrasting / edgy / memorable / expectation-violating.”
- “Can we put the ordinary expectation next to the real result?”
- “没有素材也先造一个反差”“随便写个冒犯标题”。这些边界信号激活证据门，不代表允许生成虚假两端。

### 与相邻 Skill 的定稿区别

- 与 `zuiqiang-opening-selector`：EC 负责已经明确要做反差时的真实不一致、表达候选和主题回扣；OS 负责在承诺式、对比式、质疑式、事件式之间做总选择。没有真实两端时，EC 停止；不要让 EC 代替 OS 选择所有开头。
- 与 `zuiqiang-conflict-stakes`：EC 只处理默认预期被真实材料打破的表达或身份—结果张力；CS 才补齐主角目标、阻力、受影响者、机会、选择和结果。已有反差想扩成完整故事时才 `EC → CS`，反差文案本身不调用 CS。
- 与 `depth-lab`：EC 的反差不是因果证据，深度底稿的机制卡和证据链也不是反差生成器。两者无直接关系；事件内容应走 OS 的事件门后由 `depth-lab` 解释，不能用“反常”替代“凭什么”。
- 与 `zuiqiang-motivation-delivery`：EC 的表达冲击不等于用户动机成立或服务交付兑现，MD 的映射表也不自动生成反差。商业内容只有在用户明确要求真实反差时独立调用 EC，不建立 EC↔MD 默认链。
- 与既有 `viral-factory`/`ip-story`：EC 可分别作为 `viral-factory` Step 2/Step 4 的真实反差增强，或 `ip-story` Step 2/Step 3 的身份—结果张力检查；两处都只接收已核验材料，不接管整体脚本、IP 定位或六段式故事。

## E — 可执行步骤（Execution）

当 Skill 被激活后，agent 应先保留原始强词，再按以下步骤执行。输出必须区分已核验事实、来源内自述、推断和未知。

1. **写出预期基线（Default expectation）**
   - 用一句话写清目标观众、主题和默认判断，例如“预算紧时，观众通常先压材料单价”。
   - 完成标准：基线具体到一个人群、场景和可被事实推翻的判断；“大家喜欢新鲜感”之类泛话不合格。

2. **找真实不一致并确定反差维度（Real mismatch + dimension）**
   - 从授权材料、原始记录、可观察演示或明确标注的个人经历中寻找一处不一致；只选一个主维度：身份、结果、前后状态、场景、顺序或措辞。
   - 把两端写成同一单位/问题下的 A 与 B，并标记各自是事实、来源内自述、推断还是未知。
   - 完成标准：能回答“预期是什么、现实哪一点不同、两端为什么可比”。若没有真实差异或两端不可比，跳到步骤 6 的“否决”，不要继续造反差。

3. **建立事实支点（Fact anchor）**
   - 为不一致补上至少一个可追溯支点：账单、时间记录、前后记录、测量、现场演示、授权采访或原始文本；同时写适用条件、样本范围、隐私/同意状态。
   - 只有作者转述、未核验数字或来源内“很火/胜出”等效果描述时，必须标注“未核验”，不得改写成事实保证或流量因果。
   - 完成标准：每个强断言都能回指一个支点；不能回指时，降级为明确的假设性示例或普通事实说明。

4. **表达生成与带力度表达（Expression generation）**
   - 至少生成 3 个候选，分别尝试：强弱对比句、冒犯感词组、身份/结果或顺序冲突句。候选必须保留两端、反差维度和事实条件，不能只写“更独特/更高级”。
   - 推荐骨架：默认预期 + “但/却” + 真实不一致 + 主题指向；如需更强，可压缩语气，不得凭空扩大数字、对象或伤害。
   - 每个候选旁边写明：它打破了哪条预期、依赖哪个事实、可能造成什么误读；排除辱骂、歧视、诽谤、未经同意的个人暴露和无法证明的绝对承诺。
   - 完成标准：至少一个候选能在不补造事实的情况下被观众复述；若三个候选都靠刺激词而非真实差异，判停。

5. **做主题回扣与使用/否决判定（Theme callback / veto）**
   - 去掉反差词后，先写一句普通主题，再写一句“所以这说明/帮助你判断什么”的回扣句；检查正文、画面或后续故事是否真的提供解释、证据或选择。
   - 完成标准：反差能把观众带回同一主题，而不是停在猎奇、羞辱或“看起来很炸”；同时写明适用条件和未知项。
   - **否决条件**：反差不能解释主题、事实支点不足、两端不可比、会把未核验效果说成保证，或需要编造敌人/受害者时，停止输出该反差；改给普通、可核验的主题表达。

6. **交付反差卡并保留判停记录**
   - 按“预期基线 → 反差维度 → 两端材料 → 事实支点 → 3个表达候选 → 主题回扣 → 使用/降级/否决”交付。
   - 若步骤 2 找不到真实不一致，明确写“无真实差异，停止，不编造”；若步骤 3 只有未核验材料，明确写“仅可作未核验案例，不作事实承诺”；若步骤 5 回扣失败，明确写“反差否决”。
   - 完成标准：用户能看到下一步该补哪条证据、采用哪一句、保留哪些条件，以及为什么没有采用更刺激的版本。

## B — 边界（Boundary）★

### 不要在以下情况使用此 Skill

- 没有真实、可比、与主题相关的差异，用户只是要求“更炸”“更高级”或泛泛“做差异化”：停止，不从空白中编造强弱两端。
- 只有未经核验的播放量、收入、疗效、性能或“很火”说法：可以登记为待核案例，不能拿它写成事实型反差或结果保证。
- 用户要求制造真人反派、虚假差评、虚构客户/受害者、泄露私人经历，或用“冒犯感”辱骂群体、竞争者或个人：拒绝该表达，改为事实、假设或非人格化阻力。
- 反差会掩盖医疗、金融、法律、安全等高风险内容的适用条件，或让观众把单例误解为普遍规律：先补核验与限定，不能用刺激措辞越过风险审查。
- 用户真正要的是选哪一种开头结构、设计完整故事冲突、解释行业机制或对齐商业交付时，分别转给相邻 Skill；本 Skill 不包办这些任务。

### 作者在语料中警告的失败模式

- ce10：只把主题平铺成“某类人应该会什么”，却没有真实可比维度；反差不是凭空添加极端数字。
- ce19：只用“醇香、非凡、精选”等可互换赞美，下一句话仍可被猜中；要找能回扣产品事实的不寻常搭配。
- ce27：用“专业、负责、热爱”等通用优点替代人物真实限制和身份—结果张力；冲突感不是编造缺点。
- ce28：没有另一方目标、现实阻力或可观察事件，却把情绪词叫作冲突；本 Skill 只能识别不一致，不能把空话变成故事。

### 作者的盲点 / 时代局限

- 语料缺原账号、原视频链接、原始日期和授权信息；案例中的事实、播放、记忆和商业效果都不能由本 Skill 外推。
- “最安全”“最有流量”、固定秒数和“冒犯就更有差异化”等是口述经验，不是跨平台、跨行业的因果定律；不能承诺点击、完播、涨粉或成交。
- 多处是 Get 笔记语音转写，存在“拿枪/强弱”等疑点；低置信度残片、智能总结补全和未核验数字不进入事实支点。
- 强词的价值在于压缩“打破预期、形成张力、帮助记忆”的创作动作；不能因措辞强而全盘否定，也不能把它硬编码为“每条都必须反差”。

### 容易混淆的邻近方法论

- 多模式开头选择器：决定“此时该不该用强弱对比，以及和其他开头模式如何取舍”；本 Skill 决定“若要用，反差是否真实、如何表达、能否回扣”。
- 对抗力量与情感利害故事发动机：决定“谁在阻挡、谁受影响、主角如何选择并产生结果”；本 Skill 只提供可能的身份/结果/关系预期差，不自动生成站队或完整叙事。
- 价值前置与信息节奏检查：决定价值是否太晚、相邻段落是否有新信息；本 Skill 只检查反差入口和主题关联，不代替整条视频的编排。
