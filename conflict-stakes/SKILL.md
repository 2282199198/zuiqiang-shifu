# 对抗力量与情感利害的故事发动机

> 本模块必须遵守 [不可跳步执行协议](../WORKFLOW_PROTOCOL.md)：按本模块写明的 Step、选择门、检查项和判停点顺序完成；已有输入记为该步已完成，只有用户明确要求才跳过。

本 Skill 对应阶段 1.5 的 U06。它保留来源词“敌人、可怜虫、冲突”，但把它们落实为可核对的对抗力量、受影响者/后果与选择链；“制造敌人”不是先给真人定罪，也不是先审判这些词。

在新版中，它是 `ip-story` 六段式之后的可选增强，不是默认的第二个 owner：只有六段式已经搭好、但目标、阻力、利害、选择或结果仍缺一项，且用户确实需要补足故事看点时才调用。六段式已经覆盖这些字段时保持原结构，不为“有冲突”重复加戏；本次任务仍遵守一个 owner、最多一个 enhancer。

## I — 方法论骨架 (Interpretation)

- 保留“敌人、可怜虫、冲突”这些来源词，先问它们在故事里承担什么功能。
- 从真实素材中写出主角想得到的具体目标，而不是只写“成功”或“赚钱”。
- 找到阻挡目标的敌人/障碍；它可以是同行质疑、旧观念、流程、预算、行业惯例、关系中的相反诉求或现实限制。
- 再写清谁会因失败受影响，或哪个可观察的结果会变坏；“可怜虫”是情感利害的位置，不等于必须卖惨或使用弱势标签。
- 在机会出现时让主角面对至少一个有代价的选择，选择要能改变后续结果。
- 用对抗、悬念、反转或意外呈现阻力如何变化，并把每一段绑定到事实、行动或证据。
- 结尾交代已发生的结果、尚未解决的结果和下一步；观众因此知道为什么要在意谁赢，而不只是知道谁讨厌。
- 如果目标、阻力、利害或结果没有真实材料，就补问或停下，不用“冲突”一词替空白编人、编病情、编恶意事件。

## A1 — 来源内教学/转述示例（作者亲自应用证据不足）

以下案例只作为来源内的构造材料使用。语料不足以证明它们均由讲者本人实际执行；凡标注“教学示例”或“未核验”，都不当作作者身份、真实事件或传播效果的外部证明。

### 案例 1：创业赚钱让妈妈回家过年能直起腰（创业故事）

- **问题**：只说“我赚钱了、我一路不容易”容易让观众把情绪集中到主角身上。
- **方法论的使用**：原文把舅妈的轻视作为敌人，把妈妈作为受影响者，把赚钱改写成主角争取家人尊严的机会；主角的收入不再是唯一看点。
- **结论**：敌人提供对抗，受影响者说明观众为何希望主角赢；赚钱结果必须连接到某人的处境变化。
- **结果**：原文叙述妈妈回家过年“脸上有光”，但这是来源内第一人称讲述，**人物身份与传播/观看效果均未核验**；不得把它写成外部成功案例。
- **来源**：S02《创业故事爆火公式：为什么观众不讨厌你赚钱？》，原文第 44 行，候选 `c02`（`candidates/cases.md:L32-L50`）。

### 案例 2：餐馆用回应“菜蔫了”质疑替代平铺采购展示（开店质疑）

- **问题**：只说“早上六点采购新鲜食材”是卖点清单，没有观众必须继续看的问题。
- **方法论的使用**：把“菜蔫了、同行恶意差评”的质疑绑定到主角的回应，再展示采购过程，让阻力变成可观察的验证任务。
- **结论**：开店内容中的敌人可以是具体质疑，不必编一个持续出现的反派；回应必须能证明正在回应的主张。
- **结果**：这是候选中保留的教学示例，**质疑者是否真实、拍摄是否发生及视频效果均未核验**；不能把“同行恶意差评”当作已证事实。
- **来源**：S06《短视频钩子技巧：给开店制造一个敌人》，原文第 37 行，候选 `c11`（`candidates/cases.md:L213-L231`）。

### 案例 3：老板要涨粉、员工要涨工资的人物关系冲突（IP 冲突）

- **问题**：人物只写“专业、负责、热爱”等优点时，身份关系没有可观看的张力。
- **方法论的使用**：把老板追求一百万粉丝与员工追求下月加薪放在同一关系中，双方目标不相容，于是可从对抗、反转、悬念或意外中选择呈现。
- **结论**：冲突可以来自真实关系中的目标差，不要求先造一个坏人；叙事装置应让目标和阻力的变化被看见。
- **结果**：原文没有给出实际职场事件、成片表现或关系结果，**人物身份与效果均未核验**；只能作为内容构造示例。
- **来源**：S14《IP 打造核心逻辑：用冲突感快速立住人设》，原文第 39 行，候选 `c24`（`candidates/cases.md:L475-L493`）。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 创业者有真实收入、转型或逆风经历，但成稿只剩“我赚了多少、我多不容易”，用户问“为什么观众不支持我”。
2. 店主想介绍食材、服务或门店，却有真实顾虑、差评、质疑或需要展示的回应，用户说“怎么把卖点讲成一个故事”。
3. 创始人或个人 IP 有身份反差、家庭/团队关系中的不同目标，想把流水账改成有对抗、选择和结果的内容。
4. 公共服务、产品改进或流程推进故事没有真人反派，但有预算、产权、责任、时间等可定位阻力，以及已获同意的受影响结果。
5. 用户要求凭空编“同行恶意、疾病、家庭苦难”等冲突；此时仍由本 Skill 接住做真实性和授权审查，但只交付拒绝与补问清单，不把虚构变成故事。

### 语言信号 (用户的话里出现这些就应激活)

- “怎么制造敌人”“有冲突才好看，但我不想捏造坏人/卖惨”“怎么让观众站我这边？”
- “为什么观众要在意谁赢”“我只有赚钱结果，没有故事”“怎么写出可怜虫/受影响的人？”
- “帮我把这段创业/开店/IP 经历做成故事卡”“这里能不能加对抗、悬念、反转或意外？”
- “create an antagonist”, “conflict and stakes”, “story tension”, “showdown/reversal/suspense”, “why should the audience care who wins?”
- 边界信号： “没有真实经历也帮我编”“同行恶意举报”“越惨越好”。这些触发的是真实性、授权和判停，不是放行。

### 与相邻 skill 的区分（阶段 3 定稿）

- 与 `zuiqiang-opening-selector`（`composes-with`）的区别：本 Skill 先把完整故事的目标、阻力、受影响者、机会、选择和结果搭出来；只有故事已经成形且用户还需要入口时，才 `CS → OS`，由 OS 从已有证据中选一个可兑现的开头。只要选开头不调用 CS。
- 与 `zuiqiang-expectation-contrast`（`composes-with`）的区别：本 Skill 负责谁要什么、什么在阻挡、谁会受影响、主角放弃什么来选择什么；EC 只负责真实预期差如何表达和回扣主题。已有核验反差且还要扩成完整故事时才 `EC → CS`，CS 不主动制造反差。
- 与 `zuiqiang-mechanism-explainer`（`contrasts-with`）的区别：CS 讲人物/关系的叙事利害；ME 讲产品、流程或行业事件的因果机制，即使没有真人反派也能工作。两者按主任务择一，不让“敌人”同时承担故事角色和机制证据。
- 与 `zuiqiang-motivation-delivery`（`contrasts-with`）的区别：CS 的情感后果和输赢是故事利害；MD 负责把用户改变逐项接到后端动作、证据和边界。需要把商业交付讲成故事时，先由 MD 锁定可承诺范围，再另起 CS 故事卡，不能以故事结果替代双验收。
- 与既有 `ip-story`（`composes-with`）的区别：`ip-story` 保留身份诊断、立场、六段式、内容矩阵和品牌触点；CS 只在其故事线需要时细化目标—障碍—利害—机会—选择—结果，作为故事发动机增强，不替换 IP 定位或矩阵职责。

## E — 可执行步骤 (Execution)

当 skill 被激活后，先只使用用户提供并允许使用的真实材料，按以下步骤生成一张“对抗—利害故事卡”：

1. **锁定主角目标与事实底座**
   - 从素材中记录：主角/身份、时间与场景、想得到的具体目标、已发生的事件、可引用证据、当事人授权状态。
   - 把“成功/赚钱/改变命运”改成可观察终点，例如“在截止日前提交维修申请”“让某项服务通过验收”，但不能替用户补数字或结果。
   - 完成标准：目标有对象、动作、时间或可验收状态；每个关键事实都有素材位置或明确标为“用户自述/待核验”。
   - **补问/判停**：若只有主题、愿望或一句“我想做大”，补问“谁要在什么时间、通过什么动作得到什么结果？”；未回答前停在素材收集，不写故事。

2. **补齐敌人/障碍、受影响者/后果、机会与选择**
   - 按下面字段生成草卡；只填已给事实，推测必须单独标 `假设`，不能把假设写成他人原话或事实指控：

     ```text
     主角目标：
     敌人/障碍（人、质疑、制度、流程、资源或旧观念）：
     受影响者/后果（失败时谁或什么会变坏）：
     机会窗口（为什么此刻必须处理）：
     选择与代价（主角有哪些选项，放弃什么）：
     ```

   - “敌人”必须能说明它怎样阻挡目标；“可怜虫”必须改写为具体受影响者或可观察后果；无真人反派时优先使用流程、预算、产权、责任边界、时间限制或主角过去的做法。
   - 完成标准：观众能回答“主角要什么、什么在阻挡、失败会影响谁/什么、为什么现在必须选”。
   - **补问/判停**：缺敌人/障碍时问“哪个具体质疑、限制、关系诉求或流程节点挡住了目标？”；缺受影响者/后果时问“如果失败，谁无法得到什么，或哪个结果会变差？”；缺机会/选择时问“现在有什么窗口？主角放弃哪个选项来做什么？”；关键字段仍空则停止生成，降级为问题说明/检查清单。

3. **安排对抗、悬念、反转或意外，并落到结果**
   - 从真实材料选择一种主要呈现：直接回应质疑的对抗、结果尚未揭晓的悬念、事实推翻预期的反转，或计划被现实偏转的意外；不要求四种全部使用。
   - 将故事卡补成：`阻力出现 → 主角行动/回应 → 证据或审核 → 新阻力/选择 → 已发生结果或未决结果`。每个转折都写清新增事实、动作和来源，不能只写情绪词。
   - 结尾写一条“观众为什么在意输赢”：说明谁/什么因结果获得保护、恢复通行、保住机会或仍在受影响；若未解决，明确未决状态与可执行下一步。
   - 完成标准：卡片能被复述为“目标→敌人/障碍→受影响者/后果→机会与选择→对抗/悬念/反转/意外→结果”。已解决的故事至少有一个可观察行动和一个结果证据；尚未解决的开放结局至少有一个可观察的当前状态或行动证据，并给出可执行的下一步。两者都不得在证据之外宣称主角赢了。
   - **判停**：若只能靠辱骂、疾病、家庭苦难、恶意差评或虚构数据制造情绪，退回步骤 2 改用真实限制/结果；若仍无可核对材料，交付补问清单而不是故事文案。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 用户只有一个主题、观点或想象设定，没有真实事件、目标、阻力、利害或结果；先补素材，不替用户写“敌人”“可怜虫”或结局。
- 任务只是选开头结构、做默认预期反差、查平台流量，或需要专业事实/法律判断；这些不由本 Skill 代替。
- 素材涉及家庭、疾病、客户、员工或具体个人但没有授权、去身份化处理或证据；暂停敏感叙事，改用匿名流程/结果描述。
- 目标与阻力没有不相容关系，或观众不会因任何结果受影响；不要为了“有冲突”强行安排吵架。

### 作者在书中警告的失败模式

- `ce06`：只讲收入和“我一路不容易”，没有对抗力量或受影响对象，故事会像炫耀；来源 `candidates/counter-examples.md:L130-L152`。
- `ce07`：只有敌人、没有值得被保护的对象或后果，观众可能只是在骂敌人，并不会支持主角；来源 `candidates/counter-examples.md:L154-L177`。
- `ce13`：平铺卖点、不回应具体质疑，后续展示没有要证明的主张；来源 `candidates/counter-examples.md:L304-L327`。
- `ce14`：把“制造敌人”抄成“有人骂我/同行恶意差评”的固定模板，冲突脱离事实就会变成装出来的吵架；来源 `candidates/counter-examples.md:L329-L353`。
- `ce27`/`ce28`：用通用优点替代真实冲突，或只写个人自述而不找关系、目标和限制的相反诉求；来源 `candidates/counter-examples.md:L648-L694`。

### 作者的盲点 / 时代局限

- 语料缺少原账号、原视频链接、原始发布日期和授权信息；“观众支持”“爆火”以及案例中的人物、数据和效果不能当外部事实。作者/讲者身份也未知，导出标签“船长”不等于原作者。
- “敌人、可怜虫、冲突”可能被误用成硬造反派、煽情或人身攻击；来源阶段 0 明确要求保留对抗和利害的功能，不按字面强制真人反派或卖惨（`BOOK_OVERVIEW.md:L118-L128`）。
- 这些材料主要支持编导层的看点结构，不证明冲突稳定提升播放、记忆、关注或成交；内容事实、专业质量和平台效果仍需分别验证（`BOOK_OVERVIEW.md:L123-L135`）。
- 原文含智能总结与 ASR 残片；例如“白血病/白雪冰”存在转写疑点，不能把疾病、家庭苦难或来源中的数字复制进新故事。

### 容易混淆的邻近方法论

- **攻击敌人**不是目标；先写要保护的人或结果，再决定是否需要对抗表达。坚定回应可以温和拆解，不能靠辱骂升级。
- **冲突感**不是任何争吵或负面新闻；必须能落到身份/目标/关系的不一致，以及可观察的行动变化。
- **可怜虫**不是主角自我卖惨，也不是把真实弱势者当道具；它是让观众理解输赢后果的叙事位置。
- **“敌人”先按功能解释**：优先写流程、预算、时间、旧观念、行业惯例或相反诉求；只有有真实材料、明确授权且确实构成阻力时，才写具体的人。没有材料就补问或停下，不强造反派、苦难、受害者或恶意数据。

## 相关 skills

- `composes-with`: `zuiqiang-opening-selector`（仅完整故事需要开头时 `CS → OS`）；`zuiqiang-expectation-contrast`（仅已有真实反差且要扩成完整故事时 `EC → CS`）；既有 `ip-story`（仅当六段式完成后仍缺目标、阻力、利害、选择或结果时 `ip-story → CS`）。
- `contrasts-with`: `zuiqiang-mechanism-explainer`（人物/关系叙事利害 vs 系统/事件因果机制）；`zuiqiang-motivation-delivery`（故事输赢与情感后果 vs 商业承诺—交付双验收）。二者都不默认串联。
- 无硬 `depends-on`：本 Skill 可从用户提供的真实经历或事件独立起步；若缺目标、阻力、利害或授权，先补问/停下，不调用相邻 Skill 填空。
