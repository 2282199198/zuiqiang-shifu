# 多模式开头选择器

> 本模块必须遵守 [不可跳步执行协议](../WORKFLOW_PROTOCOL.md)：按本模块写明的 Step、选择门、检查项和判停点顺序完成；已有输入记为该步已完成，只有用户明确要求才跳过。

这个 Skill 只解决一个窄问题：根据现有素材，选出一个能被正文兑现的开头主结构。它不承诺播放，不替正文补证据，也不把一条“爆款金句”当成万能入口。语料里的强词——“强弱对比”“制造敌人”“承诺—证明—为什么”——保留其劲儿，但必须先满足各自的素材条件。

## I — 方法论骨架 (Interpretation)

1. 开头的第一任务是让目标观众立刻知道“这和我有什么关系”，并给出继续看的理由。
2. 这个理由不只有一种写法，先看素材再选结构，不能先迷信模板再往里塞材料。
3. 有可交付结果和对应证明，使用“承诺—证明—为什么”，先交付，再让人相信，最后解释原因。
4. 有同一维度上的真实两端，使用“强弱对比”，让差异本身成为问题；没有可比两端就不硬造反差。
5. 有具体质疑和能展示的回应，才把“制造敌人”还原成质疑—回应—展示；敌人可以是顾虑、惯例或限制，不必是被虚构的人。
6. 有可核对事件和原因线索，才从事件开场；事件的事实、推断和未知要分开。
7. 每种开头都要把一个问题交给正文，并在正文中用对应证据、展示或解释兑现。
8. 如果必备素材不存在，诚实降级为明确的问题、观点或检查动作，不用刺激性词语掩盖素材空缺。

## A1 — 书中的应用 (Past Application)

以下均是来源内自述或教学案例；原始账号、原始视频、数据和传播因果不可得，案例效果均未核验。

### 案例 1：中专毕业经历作为承诺后的同类证明

- **问题**：开头先讲一个结果或方法时，观众会追问讲者凭什么可信。
- **方法论的使用**：S05 的语料讲者把自己的中专毕业、演讲紧张等经历放在结果承诺之后，作为与目标听众相似的证明，再解释为什么这样做；对应 `c08`，来源位置为该文件 `# 原文后第44行（同类经历证明段）`。
- **结论**：证明不一定是抽象资历，也可以是与受众相关、能核对的真实经历；它服务于“承诺—证明—为什么”，不是用经历替代交付。
- **结果**：讲者认为真实经历会带来共鸣并让人愿意听下去；没有留存、转化或事实核验材料，效果未核验。

### 案例 2：学校开业卖点改成回应质疑

- **问题**：学校开业视频需要介绍教室、大礼堂、食堂等多个卖点，直接罗列会像自夸清单。
- **方法论的使用**：语料讲者回忆自己拍过的开业视频，用“上完课就会跑”的顾虑切入，再以“开了实体学校，根本跑不了”回应并带出卖点；对应 `c10`，S06 `# 原文后第37行（学校开业段）`。
- **结论**：商业介绍可以由一个具体、可回应的顾虑发动，但顾虑必须和后续展示绑定，不能只演一场吵架。
- **结果**：原文只说加钩子“可能”更好，没有播放、咨询或转化数据，效果未核验。

### 案例 3：把“在美国生活七年”改成身份/能力反差

- **问题**：平铺“在美国生活七年”没有立即的进入理由。
- **方法论的使用**：S04 用“二十六个字母都不会”与“在美国生活七年”放在同一开篇，示范用可比较的身份/能力差替代普通经历介绍；对应 `c06`，该文件 `# 原文后第37行（美国生活标题对比段）`。
- **结论**：强弱对比的价值在于让观众追问差异如何成立；两端必须真实、相关，并能在后文说明。
- **结果**：语料称改写后“有人看”，没有链接、播放数据或对照实验；事实与效果未核验。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 用户已经有一个选题、口播稿、广告卖点或 B2B 销售主题，但问“开头怎么写”“前几秒放什么”，需要在已有材料中选入口。
2. 用户手里有一项试点结果、演示、案例或历史记录，想知道是否该用“承诺—证明—为什么”，并需要把证明放到开头。
3. 用户想用“强弱对比”或“制造敌人”让平铺内容更有劲儿，但还没有确认是否存在真实可比两端、真实质疑或可展示回应。
4. 用户做“揭秘/内幕/行业问题”内容，已有一个具体事件或记录，想从事件进入而不是先喊结论，并需要区分事实、推断和未知。
5. 用户拿着一套流行钩子模板，却发现没有结果、证据、真实反差或真实质疑；此时需要判断降级，而不是硬套。
6. 用户明确要求“没素材也先写、保证爆、编一个敌人”；此时仍由本 Skill 接住做证据门，但只交付补问、拒绝或普通开场降级，不生成保证或指控。

### 语言信号 (用户的话里出现这些就应激活)

- 中文： “这个题材开头怎么写？”“前三秒/前几句放什么？”“选哪个钩子？”“要不要用强弱对比？”“能不能制造一个敌人？”“承诺、证明、为什么怎么排？”“怎么从质疑或内幕开场？”
- English: “How should I open this video?” “Which hook fits this material?” “Should I use contrast?” “Can I use a promise-proof-why opener?” “How do I turn an objection into a response-and-demo?” “Should this be event-led?”
- 明确结构词：`开头/开篇/opening`、`钩子/hook`、`强弱对比/contrast`、`承诺—证明—为什么/promise-proof-why`、`制造敌人/objection-response`、`揭秘事件/event-led opener`。
- 边界信号： “没素材先硬写”“保证爆”“随便编个同行/敌人”。这些不是放行信号，而是激活证据门与判停。

### 与相邻 skill 的定稿区别

- 与 `zuiqiang-expectation-contrast`：OS 负责先盘点结果、证明、真实对比、质疑/回应或事件，并在四种开头模式中只选一个主分支；EC 只在 OS 确认有真实反差后，生成并验收“默认预期 → 不一致 → 并置 → 主题回扣”。用户只说“更有反差”时走 EC；用户问“该选哪种开头”时走 OS。
- 与 `zuiqiang-conflict-stakes`：CS 负责完整故事的目标、阻力、受影响者、机会、选择和结果；OS 只把已有故事材料压缩成可兑现的开头入口。只要故事结构不调用 OS；只要开头不调用 CS。
- 与 `depth-lab`：深度底稿承接事件—事实状态—机制—因果—应对的解释；OS 只检查事件材料是否足够做开场。直接问“为什么发生/凭什么/怎么避免”走 `depth-lab`；需要事件式入口才 `OS → depth-lab`。
- 与 `zuiqiang-motivation-delivery`：MD 先审计商业承诺能否由后端动作、证据和边界接住；OS 只在对齐通过且用户需要开头时，把可控交付呈现为“承诺—证明—为什么”。OS 不替 MD 修补无法交付的承诺。
- 与既有 `viral-factory`：`viral-factory` 仍负责整体内容诊断、共鸣、结构、脚本和标题；OS 是其 Step 2 开头优化之前的条件选择层，不替代工厂，也不因“写脚本”泛请求自动触发。

## E — 可执行步骤 (Execution)

当 skill 被激活后，agent 应按“素材盘点 → 条件选择 → 写开头 → 兑现检查”执行。每次只选一个主开头结构；其他素材可以后移到正文，不要把四种公式拼成一串口号。

### 1. 素材盘点

把输入整理成一张小表，至少写清：

- **对象与主题**：目标观众是谁；这条内容要回答什么具体问题。
- **可交付结果**：观众能拿到什么结果、判断、演示或下一步；标记 `有/无`。
- **对应证明**：真实经历、现场演示、授权记录、历史结果或其他可复核凭证；标记 `有/无/仅口头声称`。
- **可比两端**：同一维度的两个人、两种条件、两个结果或前后状态；标记维度、来源和是否真实可比。
- **质疑与回应**：真实顾虑/问题的原话或来源，以及能展示的回应；若只是推测，明确标成 `假设问题`，不冒充他人发言。
- **事件与机制**：具体发生了什么、手里有什么记录、能解释什么机制；分别标记 `事实/推断/未知`。
- **兑现材料与授权**：开头提出的内容在正文哪一段兑现；涉及客户、员工、疾病、家庭或敏感数据时是否获授权、已脱敏。

**完成标准**：每个字段都有值或明确写 `无`，所有数字/结果/指控都有证据状态；能列出至少一个有材料的分支，或明确所有高强度分支都不成立。

**判停 1**：如果连目标观众和要回答的问题都说不清，停止写钩子，先补充原始问题或访谈材料。若结果、证明、可比两端、质疑回应、事件记录全部为空，直接降级为普通问题/观点开场，不生成“爆款”承诺。

### 2. 条件选择

逐项检查以下四个分支的必备条件，命中的分支才可用：

1. **“承诺—证明—为什么”**：有一个限定清楚、确实能交付的结果，且有与该结果直接对应的真实证明（演示、相似经历、授权记录或可核验历史结果）。只有“我很专业”或“以后会有效”不算证明。
2. **“强弱对比”**：有两个真实、相关、可放在同一维度比较的端点，并且正文能解释差异及适用条件。只有一个孤立的夸张数字、身份标签或未经授权的竞品评价，不算对比。
3. **“制造敌人”＝质疑—回应—展示**：有具体真实质疑和可观察回应；若没有真实质疑，只能写成明确标注的“假设你担心……”并展示对应检查，不能虚构客户、同行或差评。
4. **事件开场**：有可核对的具体事件/现象、至少一条事实记录，并有可说明或待核对的机制线索。没有记录的“内幕”只是传闻，不能用事件开场指控任何人。

若多个分支同时成立，按内容任务选主分支：要先交付可检查结果，优先交付式；要解释一个真实差异，优先对比式；要回答一个购买/使用顾虑，优先质疑式；要追踪一个事实事件，优先事件式。无论选哪一个，都优先选择“能最早展示、事实推断最少”的那一个，并把其余结构降为正文材料。

**完成标准**：输出 `主分支 + 命中的素材字段 + 被排除的相邻分支及理由`。如果没有任何分支满足必备条件，输出 `降级：普通问题/观点/检查动作开场`，并列出需要补的材料。

**判停 2**：若某分支依赖未经核验的数字、竞品优劣、恶意指控或冒充他人原话，立即排除该分支；不要为了保留刺激性而继续写。

### 3. 写开头

根据主分支写一到两句能独立听懂的候选开头，保留劲儿但不把强词字面化：

- **承诺—证明—为什么**（有结果＋证明时）：先说“给谁一个什么限定结果”，紧接着放对应证据，再用一句话解释为什么这个结果/步骤成立。模板：`给[目标对象]一个可检查的[结果]；先看[证据/演示]，再解释为什么[原因]。`
- **强弱对比**（有真实可比两端时）：把两端和比较维度放在同一句，随后抛出差异问题。模板：`同样是[主题]，[端点 A]在[维度]是[状态]，[端点 B]却是[状态]；差别到底来自什么？`
- **“制造敌人”／质疑—回应—展示**（有真实质疑和回应时）：把顾虑说具体，马上承诺展示对应回应。模板：`有人/客户担心[具体问题]；我今天用[过程/记录]回应，先看[展示]。` 若是推测，必须改成 `假设你担心[问题]，我们现场检查[展示]`。
- **事件开场**（有事件＋记录＋机制线索时）：先陈述事件，再留出待解释问题。模板：`[日期/场景]发生了[可核对事件]；记录先说明[事实]，接下来拆开看它为什么发生，以及你能检查什么。`
- **降级开场**（必备素材不足时）：不装成强钩子，直接说清问题和本条能做的动作。模板：`这条只回答[具体问题]：先检查[动作/字段]，再决定要不要[下一步]。`

**完成标准**：脱离标题单独播放时，听者能说出目标对象、开头要回答的事情和继续看的理由；开头的每个结果、数字、对比、质疑和事件都能在素材盘点中找到对应状态；正文已有明确的展示/证据/解释位置。

### 4. 兑现检查

逐项把开头和正文对照，形成一条可回溯链：

- **承诺式**：承诺的结果在正文确实交付；证明与承诺同一对象、同一范围；“为什么”解释因果或步骤，不用新口号替代结果。
- **对比式**：两端真实存在、比较维度一致、差异不靠断章取义；正文解释边界，不能只留下刺激性的 A/B 标题。
- **质疑式**：质疑来源真实或明确是假设；回应是可观察过程、记录或结果；每个被抛出的顾虑都得到回答，不把冲突拖成空吵架。
- **事件式**：事件有来源/记录；事实、合理推断和未知分栏；机制解释不越过证据；结尾给检查动作、决策或下一步，而不是先定罪。

**完成标准**：把开头交给一个不看正文的人复述，他能复述“这条要给我什么/回答什么”；再把正文交给审阅者，他能从每个开头承诺找到证据、展示或解释的位置。最终交付：`主分支、开头文本、兑现位置、未核验项、下一步补证`。

**判停 3**：出现任一情况就不发布当前开头：承诺无法交付；证明只是口头声称；强弱两端不真实或不可比；质疑没有真实来源且未标为假设；事件只有传闻；敏感当事人未授权；或正文无法回答开头留下的核心问题。此时回到步骤 1 补材料，或改用降级开场；不得用“可能爆”“保证播放”等话术补洞。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **没有结果或证明**：不要套“承诺—证明—为什么”。先做普通问题/观点开场，或先补一个能展示的结果；没有交付就不能把“承诺”写成保证。
- **没有证据**：不要用历史播放量、客户成绩、竞品优劣或“现场结果”撑强钩子；降级为待验证问题、演示计划或素材清单。
- **没有真实反差**：没有同一维度的两端，就不要写“强弱对比”，也不要凭空补极端身份、数字或评价。
- **没有真实质疑**：不要把“制造敌人”抄成“有人骂我/同行恶意差评”的固定台词；用明确假设问题或普通说明，并确保有回应展示。
- **没有可核对事件或机制线索**：不要把传闻写成“揭秘/内幕”，不要替任何人定罪；转为来源透明的事实问题或交给查证流程。
- **任务本身是整条脚本的节奏、故事利害、反差文案生成或变现承诺**：分别交给相邻能力；本 Skill 只做开头分支选择和兑现门。
- **涉及医疗、法律、财务、隐私或未授权人物素材**：开头选择不能替代专业审查、事实核验、知情同意和脱敏。

### 作者在书中警告的失败模式

- `ce10`：把宽泛主题平铺成“某类人应该会什么”，却没有真实可比差异；结果是没有立即的停留问题。
- `ce11`：一上来解释原理和“为什么”，还没交付结果；观众不知道留下来能得到什么。
- `ce12`：承诺或证明无法兑现，或用未经核验的经历/数据冒充证据；短期吸引会变成吹牛和信任损耗。
- `ce13`：广告只列采购、设施或卖点，不回应具体顾虑；后续展示也就没有明确的验证任务。
- `ce14`：把“制造敌人”变成脱离事实的固定模板；没有质疑—回应—展示链，冲突只是装出来的吵架。
- `ce15`/`ce16`：把精彩信息拖到后面，或开头只报宽泛主题，让线性观看者等不到进入理由。

上述反例均来自 `candidates/counter-examples.md` 的对应条目；它们支持的是素材与结构的失败诊断，不是播放下降的外部因果证明。

### 作者的盲点 / 时代局限

- 语料缺原账号、原视频链接、原始发布日期和授权信息；“巨火”“有人看”“几百万播放”等来源内说法只能标为未核验，不能写成效果保证。
- “承诺/程度”“拿枪/强弱”等 ASR 疑点存在；本 Skill 采用候选文件中经交叉核对的安全抽象，不把疑似误听词当规则。
- “最安全”“最有流量”、固定秒数、平台推荐或降权等说法没有跨平台实验支持；本 Skill 只检查素材、结构、证据和兑现，不预测算法结果。
- “敌人”“可怜虫”“冒犯感”是压缩对抗、情感利害和预期违背的强表达，不授权虚构反派、卖惨、辱骂或伤害当事人。

### 容易混淆的邻近方法论

- **整条价值前置/节奏检查**：只判断重要信息是否过晚时，用 `viral-factory` 的整体编排检查；本 Skill 不负责逐段剪辑。
- **预期违背与可记忆反差**：如果已经确定有真实不一致，需要生成多种表达并检查主题回扣时，用 `zuiqiang-expectation-contrast`；本 Skill 只决定是否能走反差开头。
- **对抗力量与情感利害**：如果要完整设计主角目标、障碍、受影响者、机会和结果，用 `zuiqiang-conflict-stakes`；本 Skill 只处理开头的质疑/限制入口。
